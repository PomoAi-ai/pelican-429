# 坐标、单位与镜头

状态：已确认（2026-10-10）。本页是全部概念资料的坐标基准；其他资料与本页冲突时以本页为准。标注“草案”“待实测”的条目除外。

## 1. 轴与格位

| 项目 | 约定 |
| --- | --- |
| 长度单位 | 格。1 格 = 1 世界单位，镜头缩放不改变格的尺寸 |
| X | 向右为正，是左右移动方向 |
| Y | 向上为正，是高度与跳跃方向 |
| Z | **朝镜头为正**。镜头位于 +Z 一侧，看向 −Z |
| 格位 (tx,ty) | 占 X=[tx,tx+1)、Y=[ty,ty+1)，锚点在格子左下角（与 `src/world/tile-map.ts` 一致） |
| 玩法平面 | Z=0。移动、占格、碰撞只在 XY 平面计算，Z 只用于表现，不是可行走的第三条轴 |

“前”指 +Z（镜头侧），“后”指 −Z（背景侧）。资料中写“前方”“后方”时都按这个方向理解。

## 2. 深度分区（2026-10-11 确认）

| 区域 | Z 范围 | 用途 |
| --- | --- | --- |
| 前沿 | [+1,+1.5] | 格子之外的额外空间：花草、突出岩等低矮外观；不默认填实 |
| 格子 | [−1,+1] | 泥土、岩层、含矿格、空岛底岩、建筑实体；深 2，人物走 Z=0 |
| 后沿 | [−1.5,−1] | 格子之外的额外空间：背景墙、灌木、大岩 |
| 背景墙 | [−1.2,−1]，厚 0.2 | 位于后沿，紧贴格子背面，与格子零交集 |

空间带总深 3 格（[−1.5,+1.5]）。前沿、后沿不属于格子；泥土与岩层同为深 2，岩层不再向两侧露出。

## 3. 人物身体区

| 项目 | 约定 |
| --- | --- |
| 身体区 | Z=[−0.3,+0.3]，**待实测**：以人形与鹈鹕模型在各动作中的实际 Z 包络为准，实测后更新本行 |
| 后置规则 | 家具深 1 贴格子背面，占 Z=[−1,0]；人物经过时向镜头侧让到家具前沿 +0.5（深 1 家具为 Z=+0.5），越过后回到 Z=0；站上家具顶面时回到家具深度中心 |
| 前置规则 | 前沿（Z > +1）只放低矮外观，高度不超过 0.5 格，避免遮挡人物躯干与落脚线 |
| 穿模 | 游戏接受模型穿插。上述规则只用于减少穿模，不追求完全消除；空间不够时允许穿插，或用淡化处理 |

灌木整株贴格子背面，位于 Z=[−1,−0.3]，在身体区之后。树木树干贴在身体区之后（主干中心Z=−0.7，与游戏一致）；冠团用满深度、不再压扁，占Z约[−1.5,+0.3]，后半伸进后沿（树生长处不铺墙），前缘进入身体区，角色穿过树冠时允许与叶团穿插（natural-tree-definitions.md）。1 格高的花卉从前棱 +1 向前沿伸出，高于前置规则的 0.5，属已知例外，待实测决定是否降低。

## 4. 旧资料换算

2026-10-10 之前的部分资料使用“前方为 −Z”的制图坐标，并把前后预留区称为“内沿”“外延”。在这些资料统一改写之前，按下表换算：

| 旧写法 | 新写法 |
| --- | --- |
| Z 值 z | Z 值 −z（区间两端取反后交换顺序，如 [−0.25,+0.45] → [−0.45,+0.25]） |
| 内沿 / 前延半格 [−1,−0.5] | 前沿 [+1,+1.5] |
| 外延 / 后延半格 [+0.5,+1] | 后沿 [−1.5,−1] |
| 墙示例 [+0.5,+0.7] | [−1.2,−1] |

2026-10-11 前的“格子深 1、前延/后延各 0.5、总深 2”口径废止：旧中央实体 [−0.5,+0.5] 对应新格子 [−1,+1]，旧预留区移到格子之外。

## 5. 运行时对照

游戏、定义构件与透视预览是同一个实现，都按第 2、3 节运行。下表只记各对象在代码中的落点，便于核对。

| 对象 | 运行时 | 代码 |
| --- | --- | --- |
| 格子 | 地形砖与建筑块 Z=[−1,+1]；加深格 [−1.5,+1.5] | `render/tile/tile-geometry.ts` 的 `BLOCK_FRONT_Z`、`BLOCK_BACK_Z`，由 `config/definition-kit.ts` 的 `DEFINITION_DEPTH` 推出 |
| 格子形态 | 33 种形态，同格可放多块互不重叠的构件；派生的 1/4 子格掩码是碰撞粗筛与光照、流体、视线、小地图的最小单位 | `world/tile-shapes.ts`、`world/tile-map.ts` |
| 平台 | 整宽、左半、右半 × 整砖顶 j+1、半砖顶 j+0.5 六种变体；建筑平台背后有墙时挂墙，否则居中 | `world/tile-shapes.ts` 的 `PLATFORM_VARIANTS`；外观走定义构件 |
| 背景墙 | 墙层，[−1.2,−1] | `world/building-layers.ts` |
| 摆放物件 | 家具 Z=[−1,0]，太阳能板以 Z=0 居中 | `world/building-layers.ts`、`render/residence/homestead-view.ts` |
| 特殊构件 | 门、太阳能板、舰体、电梯、甲板自带碰撞，状态只在模拟步内按 tick 改变 | `world/special-parts.ts` |
| 渔屋背墙 | [−1.2,−1] | `render/building/hut-layout.ts` |
| 洞壁 | 平片，Z=−1.2（后沿里背景墙的背面） | `render/decor/cave-wall-view.ts` |
| 背景层 | 景别与层距按 depth-definitions 方案 G，世界可覆盖；近景（前景格子层）在所有世界做模糊 | `config/depth-layers.ts`、`render/backdrop/` |
| 人物让位 | 第 3 节后置规则 | `render/building/walk-depth.ts` |

渔屋门与洞壁只对齐了深度：渔屋门仍是渔屋自带的门洞（门框在 Z=[−1,−0.55]），不是 [door-definitions](door-definitions.md) 的门组件；洞壁是一张平片，不是厚 0.2 的墙。

## 6. 时间、能量与货币单位

| 单位 | 定义 |
| --- | --- |
| tick | 逻辑步长 1/60 现实秒（`TUNING.sim.step`） |
| 游戏时间 | 家园模式中 1 tick = 1 游戏秒，因此 1 游戏小时 = 1 现实分钟，1 天 = 24 现实分钟 |
| 电 | 功率。1 块太阳能板白天输出 1 |
| 电·时 | 能量。1 电持续 1 游戏小时 |
| P | 算力，PFLOPS 的简称 |
| M | 百万 Token，唯一货币的单位 |

## 7. 镜头

游戏使用透视相机，参数见 `src/config/view-tuning.ts` 的 `DEFAULT_CAMERA`：

| 参数 | 值 |
| --- | --- |
| 视角 | 垂直 fov 30° |
| 距离 | 30 格 ÷ 缩放倍率；镜头从 +Z 平视 |
| 缩放 | 0.75～2；桌面默认 1，手机默认 1.25 |
| 取景 | 人物上方偏移 1.2 格，前视 1.5 格 |

可见范围（16:9）：

| 缩放 | 镜头距离 | 可见高 × 宽（格） | 1080p 下每格像素 |
| --- | --- | --- | --- |
| 0.75 | 40 | 21.4 × 38.1 | 50 |
| 1（桌面） | 30 | 16.1 × 28.6 | 67 |
| 1.25（手机） | 24 | 12.9 × 22.9 | 84 |
| 2 | 15 | 8.0 × 14.3 | 134 |

同一物体前后两个截面的投影尺寸比（缩放 1）：格子深 2（泥土、岩层）约 1.069，整个空间带深 3 约 1.105。

### Z 方向细节在游戏中能否看清

镜头平视，物体的顶面、侧面只在偏离画面中心时才露出，越靠画面边缘露出越多。缩放 1、1080p 下：

- 画面上下边缘，1 格深的顶面约投影成 18 像素；
- 画面左右边缘，1 格深的侧面约投影成 32 像素；
- 画面中心几乎看不到顶面和侧面。

据此，Z 方向小于 0.1 格的细节在边缘也不到 2 像素，在游戏中基本不可见。例如 0.5 深的前沿在画面上下边缘约 9 像素，0.03 厚的青苔不到 1 像素。

每张定义图除设计视角外，应附一张游戏镜头视图（fov 30°、距离 30、+Z 平视），包括画面中心和画面边缘两个位置，用来判断细节是否值得制作。

## 8. 景别位置

景别由近到远：前景格子 → 可玩层 → 背景格子① → 背景格子② → 远景①②③ → 天空。

- 各层层距按 [depth-definitions](depth-definitions.md#scene-depth-distances) 的方案 G；`src/config/depth-layers.ts` 以方案 G 为所有世界的默认层表，世界可给自己的覆盖表（如城区）。背景格子是放在固定 Z 的真实几何，视差由透视自然产生。
- 远景可以是平片或几何体，挂在 `src/render/backdrop/` 的远景层里，按层距摆放。
- 背景格子需要和可玩层有明显区分（压暗或降低饱和度），避免玩家误认为可以站上去。
