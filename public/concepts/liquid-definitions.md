# 液体定义与水体透视

状态：液体定义资料，2026-10-10。程序已有水；本次补齐空间、占格、交互和读图规则，不修改液体模拟或渲染。新版深度是本次设计定义，现行尺寸另列，不能当作已经同步。

## 1. 当前只定义水

液体是独立于地形的水量层。湖泊、水池、积水、下落水流是同一种水在不同容器和流动状态下的表现，不是四种独立方块。水不是实心砖，也不是可站立的单向平台。

已有水的色板只改变外观，不产生新的液体物性。要塞已有独立的冷却液危险区域伤害规则，但格子液体没有“冷却液”类型。新增冷却液物性、熔岩、毒液、油、混合反应、温度与管道系统均不纳入本次定义。

## 2. XY 占格与水量

每个逻辑格宽1、高1，原点为(i,j)。地形与液体分开存储；每格水量q为0～255的整数，255表示满格，0表示无水。

| 状态 | 逻辑含义 | 图中表达 |
| --- | --- | --- |
| 无水 q=0 | 无液体 | 空格 |
| 部分水量 0<q<255 | 格内自底向上占据高度q/255 | 水面Y=j+q/255 |
| 满水 q=255 | 占满该格的液体容量 | 水面达到格顶j+1；上方还有水时此格是水体内部 |
| 相邻连通水格 | 共同组成水体，水量逐步流动和均衡 | 连续水面，不在内部格边画出玻璃盒接缝 |

半水位只是示意：q=128时高度为128/255≈0.502，不是精确0.5。水量单位是二维格子的归一化容量，不把现行渲染的Z厚度乘进去改变质量。

波浪、相邻水面顶点的平滑以及最小可见水膜属于外观。程序对薄水膜采用至少0.04格的显示高度，上方有水时会把下格画满；这些外观规则不增加逻辑水量，不提高游泳判定的水位。

## 3. 新版深度：水占中间1格

沿用《深度定义与线框透视说明》的设计坐标：水体位于中间Z=[−0.5,+0.5]，深1格；人物逻辑平面Z=0穿过水体中间。内沿Z=[−1,−0.5]与外延Z=[+0.5,+1]各额外预留0.5，不自动注满水。背景墙厚0.2，位于外延区；图中[+0.5,+0.7]仅是安装示例。

单个部分水格的设计包络是宽1×高q/255×深1。Z深度不随水量变化：水减少时水面下降，不把水做成越来越薄的竖向蓝片。水面为XZ顶面，正面为XY水下截面，侧面只在外露边界出现；内部相邻水格不应保留重复分隔面。

透视主图从内沿一侧斜上方观察，以看清水面和水下截面；这不是游戏默认镜头。图中的正负方向沿用建筑设计资料，不能直接替换当前程序的世界Z。

## 4. 与地形、墙、平台、门的关系

| 对象 | 定义与当前支持范围 |
| --- | --- |
| 整砖池底与岸壁 | 实心地形挡水，水留在非实心格；切开池壁后可向新空格流动。图中前面是剖切观察面，不需要额外建一面透明玻璃墙。 |
| 半砖、斜坡 | 当前液体按整格是否实心判断，不能利用半砖上方或坡面旁边的格内空余容量。水边的视觉延伸不等于形状容量模拟。 |
| 单向平台 | 当前不挡水，可与水共格；角色能落在平台上不代表平台可以作池底。 |
| 背景墙、窗与装饰 | 是前后景构件，不作为XY挡水边界；画在水后不表示容器已经封闭。 |
| 门 | 当前展示门没有液体闸门联动，不把“门关闭”解释为水被拦住。 |
| 水中放置实心格 | 当前清除该格水量并计入lostMass，不会把水自动挤到邻格。此为现状限制，不能宣称建造时水量守恒。 |

本次透视采用整砖池底、整砖岸壁，避免把尚未实现的半砖/斜坡容量画成已有能力。水可以出现在单向平台周围；平台的材质和承托规则仍复用平台定义。

## 5. 流动规则（定稿）

采用现有的二维格子重力流：**先下落，再沿可通行的同行铺开、找平，遇到台边向低处泄流；没有向上水压流。** 本节确定流动范围与验收结果，不重写已有算法。流动只改变XY格子的水量，Z仅用于水体表现，不计算前后流动。

### 5.1 下落优先

水格下方不是实心格、且水量未满255时，先向下转移水量。转移量为“本格现有水量”与“下格剩余容量”的较小值；上格扣多少，下格加多少。下格满后，多出的水留在上格，继续参与横向流动。

下方实心、下方满水或处在地图最底行时，视为有支撑。单向平台不构成挡水支撑，水能穿过平台向下流。下落分模拟步完成，不保证一帧到底；不定义真实自由落体加速度或水流速度场。

### 5.2 同行铺开与找平

有支撑的连续水段向左右紧邻、非实心且有支撑的干格铺开，再按该段剩余总量均分。实心格会截断水段，不能隔墙或跨过封闭空隙找平。

总量S分到n格，每格至少为floor(S/n)，余数格各加1；最终同一稳定水段的最大水量差不超过1。左右整数余数固定分配，允许1单位差异，不为了完全对称增加或删除水。

悬空水或未被同行均衡覆盖的水，仍可向同高度、非实心且水量更少的邻格侧流；随后继续下落。因此下落水柱可以散开，但不规定左右两边在每一步完全对称。

“找平”只指可以沿当前同行相互流通的水段，不代表整个地图的水位统一。不连通的水池互不影响；仅在底部通过U形通道连接的两池，不承诺靠水压抬高另一侧水位。

### 5.3 台边泄流与越岸

水段到达台边，外侧格非实心且其下方有空余容量时，水向低处泄出。两边都有出口时两边都可出水，并受各自接水容量限制。实际算法可把“越过台边并下落”合并为一次转移；这不允许穿过实心角，也不等于任意对角流动。

岸顶是实心格时，低于岸顶的水不会爬墙。只有上层已有来水，且水进入岸顶上方的可通行格，才可横向越岸再落下；不通过向上抽水制造溢流。来水停止后，继续转移现有水量，不凭空维持无限瀑布。

### 5.4 薄水层与静止

沿用现有最小侧流阈值4及残余目标3单位/格：水量很少时可以保留浅水膜，不要求每个台面最终完全干燥。3/255约为0.012格逻辑高度；0.04格最小显示高度只是外观。

阈值不是“少于4就冻结”：少量水仍可向下落入空格，也可能参与有支撑水段的均衡。没有可继续转移的水量时停止更新；相邻水量或地形改变后重新参与计算。静水波纹可继续播放，但不能因此搬运水量。

### 5.5 边界、地形改动与水量账

| 情况 | 确定行为 |
| --- | --- |
| 地图左右、底部及顶部边界 | 封闭边界，不作为自动排水口；禁止把越界查询得到的0误当成可接水的空格。 |
| 挖开池底或岸壁 | 新增可通水空间，唤醒邻水，按下落与侧流规则排开；挖掉实心格本身不生成或删除水。 |
| 在有水格放实心砖 | 沿用当前行为：清除此格水并累计lostMass；不自动挤水、不把这一步算作普通守恒流动。 |
| 半砖或斜坡格 | 当前仍整格挡水，不把可见空隙当作可流通的半格容量。 |
| 背景墙、窗、门和装饰 | 不增加液体阻挡；当前门没有闸门联动。 |
| 角色、小鱼与普通水花 | 不占据液体容量，不因进入水中把水挤高；水花、风致波纹不充当注水来源。 |

普通流动严格守恒：所有格子的水量总和不变，每格始终在0～255之间。若同时发生注水、主动清水或放砖，则按“当前总量=初始总量+实际加入量−主动移除量−本段时间新增lostMass”核对。向满格注水只接受剩余容量，不接受的部分不能记成已经注入，也不自动转移给邻格。

不新增蒸发、渗透、无限水源、雨水补给、虹吸、压力喷射或管道规则；这些若以后需要，单独定义，不能从“水会流动”推导出已支持。

### 5.6 推进节奏

沿用当前默认参数：每2个模拟tick推进一次，每次最多处理8192个活跃格；有支撑水段向干地扩展时，每侧每步最多并入8格。超出处理预算的格子留待后续步骤，水不能因为暂缓计算而消失。

这些是当前调参值，不是“每秒8格”的物理速度承诺，也不要求水一帧铺满整个湖。相同初始状态、配置、地形变更和注水时序必须得到相同的水量过程；不依赖渲染帧率或随机数。暂停模拟时水量停止变化；现有战斗顿帧期间也跳过液体推进。

### 5.7 验收示例

以下是规则读法与后续实现验收依据，不表示本次新增了测试或功能。

| 场景 | 应看到的结果 |
| --- | --- |
| 封闭单列竖井，顶部一格255水 | 水最终到井底，总量仍255；不是每经过一格就复制一份。 |
| 封闭的两格宽同高池底，共255水 | 稳定后两格为128与127，水面约半格高，总量仍255。 |
| 高台积水，台边下方有空坑 | 多余水流到低处；高台允许留下薄膜，不持续产生瀑布。 |
| 两池之间有高实心墙，水面低于墙顶 | 不穿墙、不爬墙，不强制把两池水位改成相同高度。 |
| 水格下方为单向平台 | 水能继续下落，不在平台上积成悬空水池。 |
| 水格q=200处放实心砖 | 该格变0，总水量减少200，新增lostMass=200；不是向左右各排100。 |
| 少量水q=2，下方是空格 | 仍能向下转移，不因低于侧流阈值而悬空冻结。 |

### 5.8 角色交互与表现

角色按身体浸没程度切换水中运动，水面不是硬地面；人形已有游泳和氧气处理。氧气取决于呼吸位置是否在水下，不能只凭脚底接触水就开始耗氧；不同形态遵循各自控制器。

当前流动定义不增加水流推人、漂浮物输送或水柱冲击伤害；水中浮力与阻尼继续沿用角色控制器。水草、小鱼、波纹、水花、焦散与水下染色不计入水格体积，不因此新增碰撞墙。

## 6. 外观与遮挡

水面应可辨认：顶面有波动和反射；水下截面半透明，随水深变化；岸边衔接池壁，深处仍保留角色和地形的可读性。连通水体内部不描出每个1×1格的盒边，格线只用于定义图。

实体岸壁遮挡水，水不覆盖到干燥地层正面。角色在水面以上的部分不被整张蓝色遮罩染色；水下部分、水草与小鱼按实际位置表现。正视、斜视与俯视均应看见一致的水面高度；不得为了俯视更明显而增大逻辑水量或改变碰撞。

这些是空间与美术验收要求，不是保证当前透明排序已适配所有旋转镜头。现行水视图以横版镜头为目标，任意角度观察仍需实际验收。

## 7. 当前程序尺寸与新定义的差异

当前程序相机从+Z看向Z=0，与上面的建筑设计示意方向不同。以下全部是现行世界坐标，不与新版坐标混用：

| 部位 | 当前程序 | 新版定义 |
| --- | --- | --- |
| 自然地形深度 | Z=[−1,+0.5]，深1.5 | 中间实体Z=[−0.5,+0.5]，深1 |
| 水前截面 | Z=+0.42，即方块前沿0.5−倒角0.06−偏移0.02 | 概念包络到内沿−0.5；渲染偏移另行适配 |
| 水背板 | Z=−1，与自然地形后沿相同 | 概念包络到外延+0.5 |
| 水面后沿 | 湖中可到Z=−1.3，靠岸1.5格范围内渐收回−1 | 限定在中间1格深度内，不默认溢入预留区 |
| 池底视觉延伸 | 向下延伸1格，由地形遮住 | 仍属防漏缝表现，不增加水量或可游泳深度 |

本次不改这些常量。以后同步新版尺寸时，游戏与展示场必须继续共用FluidMap、stepFluid、createWaterView及共享材质，不能复制一套演示专用的水。
