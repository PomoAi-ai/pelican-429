# 岩土地形组合与岩石占格定义

资料日期：2026-10-10。泥土、岛内岩层、空岛底岩和含矿岩格共同组成连续地形；独立散石是补充物件。外观可以连成一个整体，实体与可挖除范围仍按格定义。中央深1、前后各预留0.5、墙厚0.2沿用已确认规则；本页的组合布局与独立石块尺寸属于本轮设计方案。

三种组合已接入“透视 → 单独场景”，可用角色、斜视、俯视、格线及半透明检查。演示只实现布局、显示与地形碰撞，没有采矿、坍塌或资源掉落。原独立石块仍为线框资料，不据此声称已经进入游戏。

土中岩层图的实际整体包络为8×4.5×1；含矿图连同土盖及边坡的整体包络为7×5×1。场景中的站立参考地面不计入这些组合格数；空岛分区下方保持空气，不为了玩家落脚填实岛底。

## 空岛底岩的逐行连接

“挂在空岛下面”在此表示仍连接岛体的岩层，不表示已经脱离的下落物。下列每个条目均是一个逻辑格中的既有形状，保持深1；沿Y向下收尖，不占用前后预留半格。

| 行Y | 岩格位置与形状 | 连接 |
| --- | --- | --- |
| 5 | X=2为D-U，X=3～8为整砖A，X=9为E-U | 上沿接岛顶土层的下表面 |
| 4 | X=3为D-U，X=4～7为A，X=8为E-U | 接上一行，左右各收窄一格 |
| 3 | X=4为D-U，X=5、6为A，X=7为E-U | 中央保持连续实体 |
| 2 | X=5、6为J-180倒尖顶 | 顶边在Y=3与上方接合，尖端落在Y=2.5 |

倒置斜块在已有形态目录中；本轮只将所用形态装配进空岛示例，不要求实现所有可选形态的生成、挖掘或结构稳定性规则。不能因画面连成一个岛，就把整岛包围范围变成实心碰撞。

## 含矿岩格与土石交界

含矿格的场景坐标为(4,1)、(5,1)、(6,1)、(4,2)、(5,2)；减去岩层原点(3,0)，正好对应已有矿脉定义的(1,1)、(2,1)、(3,1)、(1,2)、(2,2)。原矿区3×2框中余下的格是普通围岩，不能画成隐藏矿物或空气。

本轮以共享洞穴晶体的薄化外观表示通用矿物，不指定铜、硅、铀或产量。矿色只在外露面出现，正面露头最多到Z=−0.53；相邻含矿格的露头相接，宿主仍完整深1。线框中的金色只是定位示意，不作为运行时独立矿块的体积规格。半透明模式用于检查宿主与嵌入关系，不是把正常游戏岩石定义成透明材料。

同一个XY格不能同时填一份土实体和一份岩实体。土石交界是相邻材料的接面；同材质相邻格连续衔接，格线可单独关闭。正面剖示让埋藏关系可读，未剖切的外表面仍应遮住内部物体。挖除某个宿主格后的地形变化沿用矿脉资料；本场景未提供这一操作，不能把“看到了矿色”视为已实现采集。

## 演示与共享资源

入口在基础概念的“岩土与矿产”以及透视的“单独场景”目录中。正常视角用于查看角色和地形关系，斜视/俯视检查深1；格线显示逻辑单元，半透明显示组合轮廓。空岛角色初始站在岛顶Y=7，可使用全景查看整段底岩。

三种组合统一从 `src/config/rock-terrain.ts` 的 `ROCK_TERRAIN_SCENES` 装配。砖形来自共享形态定义，泥土/石头纹理和晶体几何复用游戏资源；定义场景只是按既有深度口径装配并标注，不另画一套场景专用纹理。线框生成器从同一份TypeScript配置读取格子与轮廓，图示更新时随之生成。

## 1. 独立石块补充与线框阅读方式

![岩石尺寸、占格、承托与前后深度线框](/concepts/natural-rock-wireframe.png)

![整砖、半砖、斜坡、相邻格和移除结果的线框对照](/concepts/natural-rock-placement-wireframe.png)

图片位于 `public/concepts/`。第一张定义单体、组合与XZ俯视，第二张对照六种格子关系。线框按真实三维坐标透视投影；同一张图中的不同卡片可有不同放大比例，以标注尺寸为准。

- 深色实线表示形体棱边；地形图中的接缝同时说明形态归属，不表示运行时必须画出所有内部面。
- 蓝色虚线表示外观包络或逻辑格域，必须结合各卡说明区分；包络内的空处不填成实体。
- 灰线表示宿主或参考边，虚线也用于背侧轮廓。绿色表示前延预留或接触面，橙色表示后延区、反例及待定规则。
- 下方承托砖不计入石块尺寸。石块移除后的参考框不产生实体、碰撞或资源。

## 2. 共用坐标与深度

单位为格；X向右，Y向上，本轮镜头从−Z看向场景。参考宿主格为X=[0,1]、Y=[−1,0]、Z=[−0.5,+0.5]，顶面Y=0。这里的前方方向沿用自然资源制图约定，不能不经换算直接复制到使用其他观察方向的运行时。

| 空间 | Z范围 | 岩石相关约束 |
| --- | --- | --- |
| 前延预留 | [−1,−0.5] | 只有预留空间，没有默认承托地板；不能照搬草花向前伸出的落脚方式 |
| 中央实体 | [−0.5,+0.5] | 地形岩格深1；本轮独立石块的全部形体也放在这个范围内 |
| 后延预留 | [+0.5,+1] | 不默认摆一排悬空石块，也不成为第二排可开采岩层 |
| 背景墙示例 | [+0.5,+0.7] | 厚0.2，固定偏移仍未定；示例墙前面与独立石块后缘相距0.2 |

人物逻辑平面Z=0不等于人物没有厚度。独立石块处在中央层，不因画成装饰就自动避开角色；阻挡、遮挡和交互需分别确定。远景山石及独立背景格子不使用本页的石块承托示例，不把多层背景塞进后延半格。

## 3. 独立石块的外观与落脚

独立石块补充只定义一种标准平底款，不新增尺寸等级、随机变体或物种清单。外观为不规则多面体，底部是平面接触多边形；不是把整个包络做成实心长方体。

| 属性 | 本轮尺寸或坐标 | 含义 |
| --- | --- | --- |
| 外观宽×高×深 | 0.8×0.5×0.6 | 当前完整石块的外观范围，不含承托砖 |
| 外观X | [0.1,0.9] | 在一格宽度内左右各留0.1 |
| 外观Y | [0,0.5] | 从真实承托面量高；换承托面时整体平移 |
| 外观Z | [−0.3,+0.3] | 以Z=0居中，中央层前后各留0.2 |
| 放置锚点 | (0.5,0,0) | 位于底面内，用于与宿主位置关联，不随轮廓变化漂移 |
| 接触底面XZ顶点 | (0.2,−0.22)、(0.68,−0.25)、(0.81,0.02)、(0.67,0.22)、(0.27,0.19) | 依次连接闭合，所有顶点Y=0；完整多边形须由水平实体表面承托 |
| 宿主 | 一格真实水平支撑面 | 石块是独立物件，不把宿主砖转换成含石地形，不叠一份地形碰撞 |

接触底面的范围比外观包络小，允许边侧形体在底面外形成自然斜面，但本轮全部外观仍在宿主的一格平面范围内。绘图源文件保存三层不规则轮廓，可复现图中形体；这些顶点是制图样例，不要求未来模型逐顶点一致。

石块接触区域内不绘制穿石草叶；只避让实际底面及与岩体相交的植被，不能为了宽0.8的石块清空整格草地。石块移除后是否立即重新长草尚未定义。青苔如需附着，继续按真实外露面定义，不把苔层当作新承托台。

## 4. 不同格子上的摆放

| 情况 | 位置与判断 | 图示结论 |
| --- | --- | --- |
| 整砖 | 宿主Y=[−1,0]，顶Y=0；石块Y=[0,0.5] | 可作为本轮标准放置示例 |
| 同一逻辑格内的下半砖 | 实体Y=[−1,−0.5]，顶Y=−0.5；石块整体下移0.5到Y=[−0.5,0] | 使用实际顶面，不能仍留在整砖原顶Y=0 |
| 上半砖 | 实体Y=[−0.5,0]，顶Y=0 | 只从顶面几何看与整砖相同；上半砖本身的放置及支撑条件沿用砖块定义 |
| 左右半砖、四分之一砖 | 可用水平顶面宽0.5；当前石块接触底面横向跨度0.61 | 当前朝向的标准款不能完整落在单件上，不自动缩小石块或允许悬边 |
| 整格斜坡 | 图示坡顶Y=X−1；标准款若以最右底点X=0.81接触，底Y=−0.19 | 左底点X=0.2与坡面相差0.61，存在悬空；整体降低又会穿坡，不支持直接摆放 |
| 相邻同高整砖 | 两石X分别为[0.1,0.9]与[1.1,1.9]，外观间隙0.2 | 各自使用自己的宿主，不新增一件石块跨多个宿主的方案 |
| 前后预留区 | 本轮没有额外承托面 | 不允许仅移动Z把标准石块放进空预留区；新增托架或贴壁款需另定义 |
| 单向跳跃平台 | 平台只按现有规则承托角色；未定义物件安装关系 | 不从尺寸“放得下”推导出可安装石块，本轮不包括平台放石 |

斜坡专用石块若以后需要，应重新定义贴坡底面、整体姿态与承托范围；本轮不凭空加底座、不把岩石嵌进地形来掩盖接触问题。宽度、高度、深度分别定义，半高砖不会把石块深度也减半。

## 5. 多格岩体的精确占格

图中岩体宽3、实际最高1.5、深1，所在逻辑格域为3列×2行。原点在岩体底面左侧；下方Y=[−1,0]的三块承托砖不计入岩体。

| 逻辑格(i,j) | 使用形态 | 世界XY多边形顶点，依次闭合 | 体积 |
| --- | --- | --- | --- |
| (0,0) | D 右下实体 | (0,0) → (1,0) → (1,1) | 0.5 |
| (1,0) | A 整砖 | (1,0) → (2,0) → (2,1) → (1,1) | 1 |
| (2,0) | E 左下实体 | (2,0) → (3,0) → (2,1) | 0.5 |
| (1,1) | B 下半砖 | (1,1) → (2,1) → (2,1.5) → (1,1.5) | 0.5 |
| (0,1)、(2,1) | 空气 | 无实体 | 0 |

全部实体从Z=−0.5挤出到+0.5。共有四个有实体的逻辑格，实体总体积2.5格³；既不是六个整砖，也不是把整个3×1.5×1外观包络填实。顶格(1,1)的上半Y=[1.5,2]始终为空。

左右坡面向中央抬升，中央整砖完整承托上方下半砖。图中格界用于说明归属；运行时只隐藏真正被相邻实体遮住的内部面，仍然暴露的侧壁、半格台阶和坡面必须保留。没有要求复制图中的内部线条作为游戏材质。

此组合只复用已有A/B/D/E二维轮廓，不新增砖型，也不提升其他可选形态的实现优先级。岩体沿用所选地形轮廓的碰撞，不另套覆盖空处的大碰撞盒。统一深1是设计口径，仍需与运行时同步，不能据此声称已经实现。

## 6. 移除、矿脉和背景墙

第二张图分别画出两种移除结果：

- 独立石块移除：只去掉石块实例，下方宿主格保持完整，不留下挖矿式洞格。此对照不承诺已具备拾取或开采动作。
- 多格岩体移除顶格(1,1)：原下半砖消失，该逻辑格变为空气；原本为空的上半格不重复计算为新增洞。其他三格保持原坐标与形状，岩体最高点从1.5降到1，总体积从2.5降到2，不移动或缩放整组。

矿脉是地形岩格的含矿属性，不是另放一块重叠可采物。图中普通岩体不自动含矿；若选择含矿，应沿用[矿脉定义](natural-ore-definitions.md)的逐格储量与采空处理。剩余50%储量不等于把实体削成半砖；坡格和半砖中的矿带裁切仍须另行明确。

背景墙独立于前面的岩体；移除岩格不自动移除墙，也不把露出的薄墙当成第二份深1矿石。洞口需显示前侧岩体的真实深度与墙的位置差。

若独立石块的宿主被挖除，不能继续把它当作有支撑的摆件悬在原位。直接清理、生成掉落还是坠落尚未选择；本轮不新增重力、连锁坍塌或整组岩体倒塌系统。独立石块是否阻挡角色、能否拾取/开采、产物和再生规则也不由线框外形推导。
