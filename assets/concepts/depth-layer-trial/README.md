# 场景分层 · 景深试验（方案 G）

状态：试验中（2026-10-13）。已按第一轮评审（`task/399-review-depth-layer-trial/REVIEW.md`）修复三个渲染问题并校正结论，见第 9 节。只改了「透视 · 场景分层」页面，游戏本身与主世界未改动，未提交。

体验：<http://127.0.0.1:5174/?mode=resources&scene=depth#valley> → 工具栏点「实景」「正常视角」「跟随玩家」，A / D 走动。工具栏「原层次 / 景深 G」可来回切换，默认景深 G。

## 1. 要解决的问题

用户反馈：

1. 两层背景格子距离太近，看起来像一层。
2. 前景格子是否应该加模糊。
3. 远处是否够远。

## 2. 调研结论

一层看起来有多远，主要看人物走动时这一层跟着移动的比例（视差比例）。

- 本页是透视相机，比例 = D ÷ (D + d)。D 是相机到玩法平面的距离，游戏中为 30 格（`DEFAULT_CAMERA.distance`）；d 是这一层在玩法平面后方的格数。
- 前景在玩法平面前方，比例 = D ÷ (D − 前景格数)。

常见横版视差取值：

| 层 | 参考比例 | 来源 |
|---|---|---|
| 前景 | 1.2–1.3 | Godot 视差教程 1.3；2026 年一篇视差平台教程 1.3 |
| 近林 | 0.7–0.8 | Godot 0.7；同一篇视差平台教程 0.8 |
| 山丘 | 0.5–0.6 | Godot 0.5；同一篇视差平台教程 0.6 |
| 远山 | 约 0.3 | 同一篇视差平台教程 0.3 |
| 天边 | 0.1–0.15 | Godot 0.1；Canabalt 最远层 0.15 |

这些是各自作品或教程里的示例取值，不是通用规范，也没有给出「相邻层至少差多少才能分辨」的门槛。本试验把「相邻层比例拉开到约 0.15」当作设计目标，最终以走动时的屏幕位移和轮廓是否可辨来验收；G 方案最后两层（0.30 → 0.18）只差约 0.12。

另一个线索是大气透视：越远的层越接近天空色。单色雾只是近似，见第 2 节最后一个出处。

出处：

- <https://docs.godotengine.org/en/stable/tutorials/2d/2d_parallax.html>（Godot 官方 Parallax2D 教程，0.7 / 0.5 / 0.3 / 0.2 / 0.1 为示例）
- <https://www.gamedeveloper.com/design/tuning-canabalt>
- <https://nabigame.com/blog/parallax-platformer.html>
- <https://blog.runevision.com/2025/06/notes-on-atmospheric-perspective-and.html>（大气透视：远处地形不应比身后的天空、远山更淡；单色雾无法准确表现）

## 3. 层距对比（D = 30）

| 层 | 原层次 | 景深 G | 参考 |
|---|---|---|---|
| 前景 | +3 → 1.11 | +3 → 1.11，下沉 1 格并模糊 | 1.2–1.3 |
| 背景格子一 | −4 → 0.88 | −7 → 0.81 | 0.75–0.85 |
| 背景格子二 | −10 → 0.75 | −16 → 0.65 | 0.6–0.7 |
| 远景一（近林） | −20 → 0.60 | −35 → 0.46 | 0.45–0.5 |
| 远景二（山坡） | −43 → 0.41 | −70 → 0.30 | 约 0.3 |
| 远景三（远山） | −76 → 0.28 | −140 → 0.18 | 0.15–0.2 |
| 云（天气系统，未改） | −24 ~ −60 → 0.56 ~ 0.33 | 同左 | 美术定位待定 |

- **原层次：** 两层背景格子都离玩法平面太近（0.88 和 0.75），容易被看成可以走的地形；远山 0.28，不够远。
- **两层背景格子之间的比例差：** 从 0.132 增到 0.159。镜头移动让玩法层位移 100 像素时，两层背景之间的相对移动从约 13.2 像素变为 15.9 像素。改善存在但幅度有限；截图里的层次提升还来自雾、地面换贴图和前景下沉，不能都归功于层距。
- **第一版景深 G：** 用的是 −6 / −18，背景格子二（0.63）、近林（0.60）、云（0.56）挤在一起，已废弃。第 5 节的 compare-*.jpg 是这一版。

前景保留 +3、没有提到参考的 1.2 以上，原因：透视相机下前景越近在画面里越大、遮挡越多，现在有模糊，1.11 已能和玩法平面分开。

## 4. 实现

| 项目 | 做法 | 位置 |
|---|---|---|
| 层距 | `DEEP_DISTANCE` 覆盖 `DEPTH_LAYERS` 的距离，只在景深 G 下生效 | `src/app/perspective/definition-depth-layout.ts` `DEEP_DISTANCE` |
| 远景保持构图 | 三层远景推远后按 (D − 新距离) ÷ (D − 原距离) 放大，绕 (24, 4) 缩放，走动时移动变慢；两层背景格子保持真实格子尺寸，不放大。补偿按固定 D = 30、中心 (24, 4) 计算，只在参考镜头附近近似保持构图；本页跟随镜头的实际距离随画布高度变化，全览镜头另有取景，都不是严格不变 | 同文件 `SCENERY_LAYERS`、`SCENERY_PIVOT`、`setLayering` |
| 距离雾 | three 的线性雾按 smoothstep 计算，玩法平面后几格内几乎为零。改为对环境材质注入指数雾：雾量 = 1 − 2^(−距离 ÷ 25)，上限 0.65；背景格子一约 18%，背景格子二约 36%，近林约 62%，约 37.6 格后封顶。三层远景山脊（−35 / −70 / −140 的 `createBackdrop` 山体）全部 `fog: false`，不吃这层雾；所以同一层里普通物体和山脊的明暗关系取决于原色、雾色、光照和调色，0.65 上限不能保证远处地形一定比身后的山更深。注入在创建检查视图之前完成，线框、半透明替代材质克隆时会沿用 | 同文件 `HAZE_FRAGMENT`、`HAZE_HALF_DISTANCE`、`HAZE_MAX`、`haze()` |
| 雾与前景单独模糊只在正面镜头下开 | 侧看、俯视、绕到背后时视线不垂直于各层：按视深算雾会罩住整个场景，单独合成的前景也没有主场景深度、会错误盖在最上面。视线 z 分量 < −0.95 才启用，否则前景回到普通渲染 | 同文件 `update()` 的 `separate` |
| 前景模糊 | 前景物体同时在渲染层 0 和层 2（层 1 已被训练假人血条占用）。主渲染里前景照常进入阴影贴图，但绘制时临时关掉颜色和深度写入（`onBeforeRender` / `onAfterRender` 只在这次绘制前后切换，共享材质不受影响），所以不重复出现又不丢投影；`stage.render()` 之后用层 2 把前景单独渲染到半分辨率缓冲，横、竖两遍 15 采样高斯模糊，压暗 18%（`uShade = .82`），按预乘透明度叠回画面。模糊半径 σ = 0.24% 画面高度（第一版 0.53%，用户反馈太糊后减半） | 同文件 `renderForeground()`；调用处 `src/app/perspective/room-scene-preview.ts` 主循环 `depthEnvironment?.renderForeground()` |
| 前景下沉 | 前景组 y −1，上沿不再贴人物脚线 | `setLayering` |
| 玩法地面贴图 | 原来的定义色（米白）地面在画面里是一条亮白带，最破坏纵深感。景深 G 下把它换成与近景相同的贴图：山谷、湖畔用泥土，其余用石头。只换外观，碰撞仍是原来的实心格 | `createDefinitionDepthLayout` 的 `setGroundSkin`；`src/app/perspective/depth-scenery.ts` `groundMaterial()` |
| 切换按钮 | 工具栏「原层次 / 景深 G」，打开页面默认景深 G | `src/app/perspective/room-scene-preview.ts` `data-layering` |

## 7. 已知问题与待定

1. **云的位置。** 天气系统的云实际分布在 −24 ~ −60 格（`src/config/weather-rules.ts`），跨过新的近林层 −35。低云穿插近山不算技术错误；是否改成天边的云属于美术选择，若要改，需同时调距离、尺寸、覆盖范围和运动。
2. **只改了本页面，层距没有共享来源。** 本页和主世界共用山脊生成函数 `createBackdrop`，但层距各自写死：游戏在 `src/render/stage/stage.ts`（−20 / −43 / −76），本页在 `definition-depth-layout.ts` 的 `DEPTH_LAYERS`。只改一边不会同步另一边；推广时应先统一距离来源，再重算远山放大和画面覆盖。游戏相机 D = 30 时到 −140 为 170，最低缩放 0.75 时约 180，都在远裁剪面 200 以内；开场等其他镜头迁移时要再核对。
3. **面板「场景图层」的距离说明和「完整覆盖清单」** 仍写原层次的 4 / 10 格，未随景深 G 更新。
4. **洞厅里地面和前景都是石头。** 两者颜色接近，层次较弱；先调明度、色相和接触边缘，再判断是否需要改距离。
5. **雾色是单一颜色。** 按天空上下两色插值；不同主题的雾色、浓度没有逐个调。
6. **侧看层距视角下，放大后的远景显得很近。** 这是为保持正面构图做的放大，侧看时不代表实际观感。
7. **前景模糊只覆盖前景组创建时已有的物体。** 之后在前景组里动态新建的网格不会自动加上层 2 和绘制钩子，会是清晰的。现在前景内容都在初始化时建好。
8. **两个文件里还有别的会话未提交的改动**（例如平台参数、场景边界），不属于本试验。
9. **前景在后期处理之后叠加。** 不经过统一调色、泛光、暗角；`.82` 只是线性亮度缩放。推广到游戏时应把选择性前景模糊接进共享后期，在调色和抗锯齿之前合成。

## 8. 请评审重点看

1. 层距和视差比例是否合理，是否需要给前景更大的视差。
2. 指数雾的半衰距离 25 格和上限 0.65 是否合适；上限是否会让远处地形比远山更淡。
3. 前景单独渲染再叠回的做法：
   - 在后期处理（色调映射、调色、抗锯齿）之后叠加，前景不经过调色；
   - 渲染前临时关闭 `shadowMap.autoUpdate`、清掉 `scene.background`，渲染后恢复；
   - 这些处理是否有遗漏。
4. `onBeforeCompile` 注入指数雾时串接了材质原有的 `onBeforeCompile` 和 `customProgramCacheKey`，是否会和树木、天气材质原有的着色器修改冲突。
5. 若决定推广到游戏：应放进后期处理统一做景深，还是保留这种页面级的单独前景渲染。

## 9. 第一轮评审后的修复（2026-10-13）

| 问题 | 原因 | 修复 |
|---|---|---|
| 切换「透视线框 / 半透明」后，远层的指数雾丢失，正面可到 100% 雾量 | 检查视图在指数雾注入之前就克隆了替代材质 | 指数雾注入移到创建检查视图之前；天气云创建后再补一遍（去重） |
| 前景树不再投影 | 前景只在层 2，主相机生成阴影时按层 0 过滤，跳过了前景 | 前景同时在层 0 和层 2，主渲染中参与阴影但不写颜色和深度 |
| 自由镜头转到侧后方，前景仍盖在最上面 | 单独合成的前景没有主场景深度 | 非正面镜头不做单独合成，前景回到普通渲染（不是只停合成，否则前景会消失） |
