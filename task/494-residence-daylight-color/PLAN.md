# PLAN -- 住宅光照强化：室内日光方向性、天色进屋、前景与背景画同色

## Status: done
## Task: 494
## Related: 492, 483, 471

## Goal
- 白天室内不再均匀发亮：压低室内环境光下限，由天光网格主导明暗；窗边亮、房间深处明显变暗；窗下墙面与地板有柔和日光斑和淡光束。
- 天光带天色进屋：天光网格亮度乘当前天空颜色参与照明，傍晚偏暖、阴天偏冷、夜里偏蓝。
- 前景与背景画光色一致：主光、补光、轮廓光按时间使用一套与背景画相符的配色，15:30 前景不再是中性白；人物有暖色轮廓光。

## Non-goals
- 投影与阴影贴图范围、bloom、夜间灯光外漏、水面反射、家具挡光、性能排查。
- 不改光照网格的传播规则（492 的泰拉瑞亚规则保持不变）。

## Acceptance Criteria
- 15:30 住宅室内：窗边墙面与房间中部亮度差明显（截图取样差值显著大于现在的约 6/255），深处不死黑。
- 15:30 与日落时室内带暖色，阴天偏冷，夜里室内天光部分偏蓝；灯光池颜色不受影响。
- 15:30 前景平台与人物的光色与背景画色调接近，人物轮廓有暖色边光。
- 夜间、地下视角无回归。
- `npm run typecheck`、`npm test`、`npm run build` 通过。

## Constraints
- 游戏与展示场共用光照模块，修复写在共享模块。
- 逻辑层不依赖 three/DOM；边界校验一次，不加防御性兜底。
- 工作区有其他会话的并行改动：只改本任务涉及的文件，定点编辑。
- 不提交、不推送。

## Decisions
- 探索结论（室内）：半球光、环境图漫反射/镜面与方向光都已乘天空光 `sky`（`residence-lighting.ts:283-301`），CPU 光场在两窗之间约 .4、窗旁 .75～.9，按模型应有约 1.9 倍亮度比，但实测只有约 1.1 倍；可疑项为白天灯光按 `sky` 反向补偿（sky<.35 时灯回满，`:264`/CPU `:356`）、对所有 sky<1 格生效的 `(1-sky)` 底光（`:294`）、灯色反射与后期。窗格只做天光种子，不放主光进屋。只有住宅与自由搭建场使用该着色补丁；搭建场的帧回调拿不到 atmosphere。
- 探索结论（配色）：前景灯光按世界时间插值，10 月日落 19:00，15:30 时 daylight=1、twilight=0，key `#fff2e4`、hemi `#eef1f5`、rim `#d9e5fa`×.35，环境图与雾为蓝天白地平线；原版住宅背景 `public/scenes/ai-city-skyline-v3/` 是固定黄昏原画（天空均值 `#a39de0`，地平线橙粉 `#f4a4b1`/`#fcada3`，楼群 `#585d94`），不随时间着色。`ai-city-lighting` 被住宅、搭建场、材质库、场景演示、设施五处共用；rim 方向写死 (.6,.5,-.8)。
- 配色方案（分叉取舍）：背景是固定黄昏原画，前景改用“取自原画”的住宅专用配色，白天也保持原画的暖桃主光与淡紫补光，时间只驱动强度与夜晚；不给原画按时间着色。只作用于原版住宅（harbor 变体与其他页面沿用现有配色），理由：用户要求前景与背景画一致，原画只有一套黄昏版本。
- 设计（architect）根因推断：白天灯光按天光反向补偿（sky 越低灯越亮）把天光梯度抵消，加上 sRGB 把线性比压到约 r^(1/2.4)，再叠 `(1-sky)` 底光，实测只剩约 1.1 倍；实现前先在浏览器做像素诊断确认。
- 设计 A：天光项改乘 `sky^1.5`（只作用于环境/半球/IBL，方向光门控仍用线性 sky）；地上白天灯光按常量折减，只有地下沿用天光门限；`(1-sky)` 底光地上留 35%、地下不变；CPU 点光折减同步。
- 设计 B：着色器里逆太阳方向在光场中搜索天光种子（窗/门洞），命中即为窗的投影：地板实心表层为光斑（主光的 .8），空气中背墙为淡光束（.25），离窗渐淡、遇实心停止，颜色直接用主光；否决按窗加叠加面片（光场无窗数据、透明排序与重建成本）。
- 设计 C：`ai-city-lighting` 由当前地平线色算出亮度归一、半饱和的 `skyTint`，并入室内反弹项按深度渐入（露天不生效），避免与环境图重复染色；住宅与搭建场经 `setFrame` 传入。
- 设计 D：`AI_CITY_LOOK` 去掉 `as const`，硬编码的 haze/sunset/dusk/rim 方向移入，新增 `AI_CITY_RESIDENCE_LOOK`（暖桃主光 `#ffd8be`×3.4、淡紫天光 `#e3dcf7`/`#b8a3ae`×1.3、暖边光 `#ffb59a`×.9 方向 (.8,.25,-.55)、天空 `#8f88d6`/`#f4a4b1`/haze `#fcada3`、雾 `#c4a3c9`、晨昏 `#ff9f86`/`#5b5a9a`/`#f79a8c`），`createAiCityLighting(stage, look)` 只在原版住宅传入；夜间沿用共享配色。
- 无停止条件（分叉已按用户“前景与背景画一致”取舍，改动可逆、无外部影响），直接实施。
- 实施前像素诊断（15:30，下层后墙，窗右侧 vs 两窗之间，9×9 均值）：基线 (183,175,172) vs (131,124,121)，亮度差约 52/255（与探索记录的约 6/255 不符，现工作区已有约 50 的梯度，但整体中性、深处不暗）；`quality=low` 相同（后期不是原因）；临时关闭白天灯光漫反射只让灯下后墙降 10～20、取样点几乎不变；临时去掉 `(1-sky)` 底光让两窗之间只暗约 4。结论：主因是天光线性衰减经 sRGB 压平与整体中性配色，灯光补偿与底光是次要项；临时代码已还原。
- 实施后同点：(209,162,151) vs (130,88,77)，亮度差约 75/255；深处 (127,85,72) 不死黑。
- 配色调参：按设计原值（skyBottom `#f4a4b1`、haze `#fcada3`、hemiGround `#b8a3ae`）室内呈品红（两窗之间 (139,82,91)，环境图线性色比约 1.43:.86:1.15，紫顶+粉地平线+紫灰地面合成品红）；skyTint 置白只改变约 10，品红来自环境图与半球光而非反弹。改为 skyBottom `#f4bca8`、haze `#fcc8a4`、hemiGround `#c8b4a2`（环境比约 1.32:.92:.89），室内为暖桃色；其余配色按设计原值。
- 窗下日光调整：按设计原样会让露天地面顶面与临水侧面也多一层主光。加两条门控：乘 `(1-主光逻辑透过率)`（主光循环里记下 `residenceSunVisible`），只补阳光直射不到处；搜索须先经过一段室内空气（遮挡 <.55 且天光 <.9）才计命中，露天地面侧面紧贴天空不再误判。其余参数（12 步×.3、遮挡 .55、命中 smoothstep(.9,.98)、spot .25/.8、sky .02～.97）保持设计值；后墙光束 15:30 增亮约 20～25/255，上层楼板表层有光斑。
- `createAiCityLighting(stage, look = AI_CITY_LOOK)` 保留默认参数：其余三处调用（搭建场、场景演示、设施）不改，diff 最小。
- 浏览器：15:30/18:45/23:00 原版住宅、住宅 2（沿用共享配色）、自由搭建场加载无控制台错误；夜间灯池正常；演示存档地下无灯，地下灯白天满功率仅按代码路径确认（地下分支与改前公式相同）。截图见 `evidence/`。
- 审查：无 Critical。Non-critical“地上白天灯固定折减使无窗封闭房间近乎全黑”已改：白天折减改为按天光门限，地上门限取 .08（`LAMP_ROOM_SKY`）、地下 .35，有窗房间深处天光高于门限不受影响，封闭房间白天灯满功率；着色器与 CPU 曲线同步。改后 typecheck、residence/lighting 测试（91）、build 通过。
- tester-general 未单独派发：实现方已运行 typecheck、npm test（1977/1977）、build 并完成浏览器验收；修复轮只改一处门限常量，补跑 typecheck、受影响测试与 build。
