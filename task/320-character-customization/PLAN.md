## Goal

设计支持男性、女性主角的捏人功能，保留项目现有角色风格，并复用正式游戏的模型、骨架、动作和装备。设计后用户已同意逐步推进，当前完成第一步女性概念图，本文不是整套功能实现完成记录。

## Non-goals

- 当前小步仅新增女性概念图及生成记录，不修改游戏代码、模型或既有未提交改动，不提交、不推送。
- 首版不加入自由身高、四肢长度、全身体型滑杆、自由雕刻、照片生成角色、云端账户或外观商城。
- 首版不增加服装款式切换、拖地长发或布料模拟；不改变鹈鹕外形与战斗数值。

## Decisions

### 1. 男、女两套基础外形，共用一套骨架与动作契约

女性单独制作头脸、身体轮廓、服装版型与蒙皮；男性以现有 Grassy 为默认原型。两套网格不要求相同顶点数，但必须遵守相同骨架名称、层级、绑定姿势、关节位置、坐标和尺度。

首版保持肩、肘、腕、髋、膝、踝的骨骼位置一致，通过网格体积和服装剪裁形成不同外形。复用当前 22 骨骼和 15 个动作，身体比例不通过任意缩放骨骼调整。若女性轮廓在这些约束下不自然，先调整资产设计，不承诺直接复用不兼容动作。

美术方向为与现有主角一致的风格化冒险者：女性有独立脸部轮廓和自然身体比例，沿用针织上衣、裤装、平底鞋及键盘/背包的整体主题。配色与发型不按性别锁定。首版固定两套服装版型，只开放颜色。

### 2. 首版功能范围

| 分类 | 首版目标 | 资产条件 |
|---|---|---|
| 基础外形 | 男性、女性 | 两套正式蒙皮模型 |
| 预设 | 每种外形 3 套，共 6 套 | 参数组合，不复制整套模型 |
| 脸部 | 脸宽、脸长、下颌宽、下巴长度、眼睛大小、眼距、鼻子大小、嘴宽，共 8 轴 | 男女分别制作同语义 shape keys，独立校准范围 |
| 发型 | 原版短发、侧分短发、短波波、束发，共 4 款目标 | 每款适配两种头型，全部为需验收的资产工作 |
| 颜色 | 肤色、发色、上衣、裤子、鞋子 | 有明暗细节的中性底色与独立材质分区 |
| 操作 | 预设、微调、随机、分类重置、恢复默认、应用、取消 | 随机先选校准预设再有限扰动，不随机到未经验证的极值组合 |

不使用一个连续的“性别滑杆”。两种基础外形是明确选择，脸部参数在各自基础外形上调整。

### 3. 脸部形变与动画分工

使用 Blender Shape Keys → GLB morph targets → three.js 权重的既有链路。8 个 UI 参数统一为 [-1, 1]，0 为所选基础外形的中性脸；负向和正向分别映射到制作好的形变，具体幅度由男女各自资产决定。

按语义名称绑定形变，不按跨模型顶点索引或固定 morph 数组下标绑定。外观只写 Face 前缀的通道；眨眼只写 Blink/BlinkHalf；发型动态只写 Hair 通道。不得清空其他系统的权重，动画切换和复活也不得重置脸型。

眼距、眼睛大小等参数同时处理脸部、眼球周边和四片眼睑。BlinkHalf/Blink 需在可调范围内贴合，必要时由资产提供针对眨眼的修正形变。先校准允许范围，再开放滑杆；不能用一个独立眼皮缩放冒充完成适配。

脸宽等轴限制在不改变头顶和发根贴合区的范围内，以保持发型适配。发型使用共享 head 挂点，保留独立几何和动态骨骼。

### 4. 配色优先使用独立材质

本次需要制作女性和可换发型资产，顺便把皮肤、上衣、裤子、鞋子整理成明确材质分区，保留纹理与法线细节。优先使用原生材质颜色，避免首版新增一套多区域染色 shader。

可调区域提供中性底色贴图，避免在已烘焙的深色衣服和棕色头发上直接乘色。肤色同时覆盖耳、手、眼睑，保持嘴唇、眼白等细节。分材质增加的 draw calls 在代表性手机上测量，发现实际预算问题后再评估遮罩合批，不预建两套方案。

### 5. 最新代码现状与必改点

- `src/render/grassy/grassy-rig.ts` 当前恢复原版合并头发，`readAsset()` 拒绝主体已有 position morph，`addHairSway()` 会清空主体 position morph。这两处会阻断捏脸，必须随新资产契约一起改。
- 之前探索时存在的主角两款独立发型已不在当前生产配置中；磁盘历史或未跟踪资源不等于已完成适配。新发型从真实资产验收开始。
- 新捏人资产将头发从身体分离，移除主角主体上按固定坐标生成发梢形变的接入；使用 `src/render/hair-rig.ts` 的独立发型机制。NPC 使用的共享发梢函数不顺带重构。
- `createGrassyRig()` 已按实例克隆材质，可复用。geometry、贴图由资源缓存持有；外观权重、材质副本和骨架属于实例，禁止修改缓存中的基础 geometry。
- `grassy-motion-pose.ts`、`grassy-effects.ts` 依赖动作节点、轨道与挂点；两套资产都保留 FlightHarness、KeyboardWeapon 和现有特效节点。
- 骑行使用现成烘焙动作，没有为不同骨长实时求解 IK；这是首版固定骨长的原因。
- `grassy-death.ts` 使用共用骨架和固定倒伏偏移；逐一检查两套模型倒地效果，只有确有差异时才引入资产级校准参数。
- `web-models.ts`、`build-web-models.ts`、`build-compact-models.ts` 构成正式资源链路。女性、头发及所需派生资源必须纳入发布清单；shape keys 的名称和压缩精度必须保留。
- `GRASSY_HEIGHT` 当前把发梢高度算入 3.1 格。拆出发型后改为分别验证身体/骨架尺度与发型允许包络，不能用每款发型最高点重新缩放整个人；碰撞尺寸继续来自 `player-form.ts`。

### 6. 编辑交互

首版复用主菜单与游戏暂停菜单入口，以同一角色编辑面板承载；不另建资源展示站点或专属模型实现。

桌面：左侧约 60% 为角色，右侧为参数；手机：上方角色，下方可滚动参数，底部固定应用/取消。分类顺序：基础外形与预设 → 头发 → 脸部 → 配色。

预览支持旋转、缩放、正面/侧面、头部/全身、实际游戏视距。动作提供待机、跑步、攻击、骑行、飞行的快捷选择，内部仍使用正式动作器。

首次进入使用现有男性默认外观，不强制重建角色。选择男性/女性基础卡会加载该类型默认预设，卡片注明“切换将重置当前脸型与搭配”；点击具体预设加载其完整配置。取消可恢复进入编辑前的外观。

滑杆用可键盘操作的原生控件，显示数值、名称和重置按钮；色板同时提供文字名称与选中状态，不仅靠颜色表达；支持现有中英切换和触屏。

### 7. 数据、保存与应用

一个 `CharacterAppearance` 对象包含 version、body（male/female）、hairId、8 个明确命名的 face 参数和 5 个配色项。存储完整结果；presetId 不作为还原角色的必需条件，不把性别写进战斗实体。

存储使用独立 localStorage key，首版只保存一套已应用外观，不绑定主线存档。完全没有保存数据时使用显式默认值；JSON 损坏、版本不支持或资源 ID 无效时显示具体错误，并提供用户主动恢复默认的操作。

进入面板复制已应用配置得到草稿；所有调整只作用于预览实例。点击应用前等待必要资源加载，创建可用的新玩家视图并验证，再写入存储、切换外观。存储失败时保留旧玩家视图和旧应用状态，显示错误并保留草稿供重试；丢弃未提交的新实例。

游戏内编辑时暂停模拟、隔离游戏输入。仅重建玩家表现对象，保留实体、位置、血量、冷却、当前形态与任务进度。玩家死亡、变身或传送尚未完成时，暂时不允许打开编辑并显示原因，避免在过渡动画中替换视图。关闭面板后恢复原暂停状态。

异步模型加载沿用展示场的请求序号做法：快速切换、关闭面板后，旧请求不得覆盖新选择。缓存按基础外形、模型档位和贴图规格区分，头发按资产 ID 缓存；清理临时实例不能销毁仍由游戏使用的资源。

### 8. 实施顺序

1. 资产试制：男性保留原型，制作女性正面/侧面/背面方案与基础网格；在同一骨架上验证跑步、骑行、握键盘、背包间隙。此步尚不声称美术定稿。
2. 最小可运行样件：男女都支持脸宽、下巴长度、眼距和肤色/上衣色，跑通原始及 compact 资源；同时验证眨眼和头发通道互不覆盖。
3. 资产扩展：完成 8 轴脸部、4 款双头型适配发型、独立服装配色、6 套预设。若原脸拓扑不足以自然变形，先局部重拓扑、重做蒙皮与贴图转移，不靠扩大滑杆范围遮掩问题。
4. 编辑器与存储：完成草稿、预览、取消、应用和失败提示；接入菜单与当前玩家视图。
5. 游戏/展示场同步与交付：覆盖正式资源档位，完成动作、生命周期、手机性能与浏览器人工验收。

最小样件是中间验证，完整首版必须含女性与真实捏脸，不把配色面板当作捏人完成。
