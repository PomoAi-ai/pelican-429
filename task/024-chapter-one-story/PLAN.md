# PLAN -- 第一章开场：序章接故事三幕

## Status: implementing
## Task: 024
## Related: 018, 022, 023
## Baseline Commit: 无 HEAD；仓库文件全部未跟踪

## Goal
在现有 `?mode=intro` 序章（代码→AI 乐章→GPT 诞生→高潮→第一幕）之后接入故事：第二幕屏幕失控（降智、路由、封号、gpt4omini、gpt5.6luna 飞出，Grassy 眩晕），第三幕痛苦梦境变身鹈鹕、轮子满天飞始终组不成自行车，第四幕以鹈鹕形态坠入游戏世界，最后给出游戏目标（对抗 AI 邪恶势力、最终变回人形）并可进入游戏。四幕各自全屏、依次单独展示，可从控制栏单独跳转到每一幕。

## Non-goals
不改序章已验收的乐章结构与词表；不重新生成概念图；不改游戏模拟、vendor、CI；不提交推送。

## Acceptance Criteria
- 时间线：0–20 秒序章（不变）；20 秒第一幕雨雪夜编程；25.5 秒第二幕失控；32 秒第三幕梦境；39.5 秒第四幕游戏世界；45 秒出现目标；总长 49 秒。
- 每幕是单张全屏概念图加画布动画，没有拼图或四宫格；控制栏可以直接跳到序曲和第一到第四幕。
- 第二幕的文字从显示器方向逐个按拍飞出，不用方框。「封号」必须出现，并且是最醒目、停留最久的一项；随后进入眩晕效果（重影、摇晃、暗角）。
- 第三幕：画布绘制的辐条车轮多次扑向车架，每次差一点就装上又被甩开或瞬移，节奏逐渐加快，最后疯狂收束。
- 第四幕：鹈鹕落地时有重拍和镜头冲击，之后转为平稳的游戏世界；目标文字使用英文：FIGHT THE ROGUE AI / BECOME HUMAN AGAIN。
- 音乐与画面共用同一时间表：失控刺音、「封号」重击、眩晕颤音和心跳、梦境加速节拍与车轮呼啸、落地重音和解决和弦。
- 暂停、拖动、重播、静音、跳转在任意幕都保持音画同步；离开页面时释放资源。
- 结束时只出现一张目标卡片（附进入游戏链接），不在画布上重复绘制同样的目标文字。

## Constraints
- 不新增依赖；继续用 Canvas 2D 和 Web Audio。逻辑层不受影响。
- 序章词语仅英文、无年份。故事中的「降智」「路由」「封号」按用户原话用中文，其余异常词用英文或模型名。
- 视觉与音频不写自动测试，由浏览器人工检查。
- 不加防御性兜底；图片加载失败直接报错。

## Decisions
- 跳过 explorer：018/022/023 已完整覆盖序章文件，本轮已直接阅读 intro-app、intro-canvas、intro-audio、intro.css、config/intro 和四张概念图。
- 跳过 architect：改动按文件逐项写明（见下），无方案分歧，也不满足任何停止条件，因此直接进入实现。
- 场景图：第一幕 01-…-v3-mac-studio，第二幕 02-…-v2-account-ban（含封号），第三幕 03-transformation-concept-v1，第四幕 04-enter-game-world-concept-v1。四张都是 1672×941。
- 时间基准：序章保持 score 时间（真实时间 × 1.6）；故事部分（从 20 秒开始）全部使用真实秒。时间表集中在 config/intro.ts，音画共用。
- 故事节拍为 120 BPM，每拍 0.5 秒。失控词在 26.0、26.5、27.0、27.5 秒依次出现；28.0 秒留一拍空白，28.5 秒「封号」重击；29 秒起眩晕。梦境中车轮的尝试时间为 33、34.25、35.25、36、36.6、37.1、37.5 秒，逐渐加快；38 秒短暂静止，随后疯狂收束到 39.5 秒。第四幕 41.5 秒落地。
- 目标文字放在 HTML 结尾卡片（复用 .intro-chapter），45 秒出现，不在画布上重复。
- 用户要求重新设计 0–20 秒序章。旧版曾经历两个极端：词云杂乱，或者居中幻灯片过于呆板。新版取中间路线。
  - 时间：去掉 1.6 倍的 score 时间，全程使用真实秒，并与故事共用 120 BPM 网格（每拍 0.5 秒，每小节 2 秒），共 10 小节。用节拍细分和力度推进高潮，不靠加速。
  - 段落：0–4 秒逐字敲代码，每次按键都是打击声；4–8 秒代码行拉伸成五线谱，字符落成音符，NEURAL NETWORKS 和 DEEP LEARNING 依次出现；8–10 秒 TRANSFORMER 用注意力弧线连接字母，9.5 秒休止一拍；10 秒 GPT 诞生，G、P、T 分三拍重击，带冲击波，音符被吸向它；12–16 秒依次出现 GPT-2、GPT-3、ChatGPT、GPT-4、GPT-4o，入场方式各不相同，后一个把前一个撞出屏幕，鼓组和和声进行在这里加入；16–18 秒 AGENTS 和 CODE WRITES CODE 推到高潮，用 16 分音符；18 秒起连续三拍齐奏重击，19 秒硬切黑场并出现标题，20 秒进入第一幕。
  - 主次：同一时刻只有一个主词，位于中心；次要的编程/CI 术语用小号、暗色，沿放射方向飞出屏幕；音符作为装饰流。不使用方框或格子。
- 用户确认暂不做 3D，因为现有 3D 模型效果不满意；故事继续采用概念图加画布动画。用户还要求设计不要局限于提示词，因此对序章的创意概念做了加强，内容如下，以此为准。
  - 代码即旋律：每敲一个字符，就按五声音阶奏出一个音，打出的代码本身就是旋律；字符升起后化作音符。
  - GPT 诞生：人敲下半句，光标停顿一拍，之后机器用金色文字自动续写，紧接着 GPT 重击出场。生成式补全就是这一幕想表达的意思。
  - GPT 谱系：每一代名字出现时，背后机器书写的文字更长、更快，用文字的速度和密度表现能力的增长。
  - CI 作鼓机：build、test、deploy 带对勾的小词以 hi-hat 节奏飞出，从屏幕边缘离开。
  - 高潮：人与 AI 像爵士乐那样交替呼应。人写一行（青色，左侧），AI 回一行（金色，右侧），每轮从一小节缩短到两拍、一拍、半拍，最后两边同时落下齐奏重拍。主词为 VIBE CODING，随后硬切黑场，进入 Grassy 在雨雪夜进行氛围编程的第一幕。
- 用户指出 AI 演进不能只有 GPT 系列，序章词表据此调整如下，以此为准。全部英文，不写年份，大致按时间先后排列。
  - GPT 之前，智能的序曲：ELIZA → DEEP BLUE → ALEXNET → ALPHAGO → TRANSFORMER。
  - GPT 诞生仍是唯一的重点，保持“人写半句、机器续写、GPT 重击出场”的演出。
  - GPT 之后，整个生态像乐团一样逐一加入，每个模型族对应一个声部或音色：BERT、GPT-2、GPT-3、DALL·E、COPILOT、STABLE DIFFUSION、MIDJOURNEY、CHATGPT、LLAMA、CLAUDE、GPT-4、GEMINI、MISTRAL、QWEN、SORA、GPT-4o、DEEPSEEK、o1。主次安排：只有 CHATGPT、GPT-4、CLAUDE、GEMINI、DEEPSEEK 以主词形式出现，其余作为次要声部环绕或飞过，同屏一次只有一个主词。
  - 到高潮时整支乐团齐奏，人与 AI 交替接句，最后落到 VIBE CODING。
- 用户纠正了标志性版本，以下取代上一条中的模型列表：
  - 主词依次为 CHATGPT → GPT-4 → DEEPSEEK-R1 → CLAUDE 4 → GEMINI 3 → CLAUDE 5。
  - Gemini 只出现 GEMINI 3。
  - CLAUDE 4 之后，4.1、4.5、4.6、4.7、4.8 逐拍上行攀升，配上行音阶。
  - CLAUDE 5（副标题 FABLE · MYTHOS）作为升华：乐曲升调，萤火群上升，然后直接进入高潮。
  - 次要词包括 GPT-5、KIMI 等。
  - 用户要求 GPT-6 ASTRA 必须出现：在 CLAUDE 5 之后作为主词出场，萤火升空化作星座拼出这个名字，形成第二个峰顶，随后进入高潮。
  - 版本顺序以公开发布时间线为准（2026-10 检索 temperature2.com、tech-antenna.com 的时间线），画面上不显示年份。
- 用户指定序章从漆黑中出现的一只萤火开始，并要求不受原提示词限制。萤火作为贯穿序章的主线，含义依次是：一个火花、光标，最后是乐团。
  - 开场：萤火在黑暗中随拍子明灭，用光的轨迹写出第一行代码；每个字符对应一个音，写完后字符升起，化作音符。
  - 前奏：萤火依次点亮 ELIZA、DEEP BLUE、ALEXNET、ALPHAGO、TRANSFORMER，每个词的点燃方式都不一样。
  - GPT 诞生：萤火停成光标，人写下半句，机器用金色续写，GPT 重击出场，同时萤火分裂成群。
  - 乐团入席：此后每个模型由一只新萤火带出，颜色各异，对应不同的声部。
  - 高潮：借用萤火同步闪烁的真实现象，所有萤火最终在重拍上同时闪亮。用“同步”表现高潮的秩序，而不是混乱。
  - 收尾：萤火群塌缩成一点后熄灭，接黑场、标题，然后进入第一幕。
- 用户要求第二幕重点表现 gpt6-astra 被映射成 gpt5.6luna 和 gpt4omini，与序章中 GPT-6 ASTRA 的荣耀形成反转。演出：金色的 gpt6-astra 出现 →「路由」将它乱码改写成 gpt5.6luna →「降智」再把它降级为 gpt4omini → 空一拍 →「封号」重击。每降级一次，配一个音高下沉的下行滑音。
- 并行冲突：另一个会话同期完成了 026（多路线协奏序章），并在进行 027（十套开局目录，?mode=intro&opening=<id>）。用户决定把萤火乐章作为第 11 套开局接入 027 的 editions 体系，不覆盖那十套。接入要等 027 完成之后。第二幕的 gpt6-astra 映射是各套开局共用的故事内容，在接入时一并修改。
- 实现分工：序章的新代码先写进独立的新文件，避免和第一位实现者在 intro-canvas、intro-audio 上的修改冲突。等故事部分完成后再接入，并删除旧序章和 score 时间。
- 序章重写放在故事三幕完成之后再派，避免两个实现者同时修改 intro-canvas 和 intro-audio。
