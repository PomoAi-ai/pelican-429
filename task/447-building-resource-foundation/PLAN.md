## Goal
完成基础概念 Markdown 单一来源、HTTP 文档与 llms.txt、统一资源分类命名和资料库、四小块组合与加深互斥、两格方石合缝、平台和共享材质、自由搭建场接入、AI 住宅资源替换。

## Non-goals
不制作红木家具系列，不修改角色资产，不提交或推送，不删除用户存档。

## Acceptance Criteria
- 基础概念全部正文由 HTTP 可访问的 Markdown 渲染，交互演示保留；复制 LLM 说明包含简述、当前文档与索引绝对地址。
- 资料库包含旧天然材料和现有建筑、平台、门窗、家具、灯、植物、设备、装饰，名称、尺寸、规则与实现状态准确。
- 同格四小块可独立放置和编辑；任一加深部分禁止整格背景墙，双向检查。
- 米黄色方石为通用格子，相邻两格视觉合缝而保留逐格编辑。
- 平台所有已有变化保留，承托高度正确；材质具有稳定变化与动态光照。
- 所有可建造资源可在自由搭建场使用，住宅复用统一资源和可编辑地台。
- 类型检查、全量测试和构建通过，浏览器核对 HTTP、文档、搭建和住宅效果。

## Constraints
- 当前工作区有大量已有改动，仅改本任务涉及部分，不回退其他工作。
- 共享游戏配置与生成器，不能为资料库另做一套尺寸、材质或模型。
- 文档保留已确认／待实现区别。存档资源标识保持稳定，展示名称可以改变。

## Decisions
- 按用户已批准的目标直接实施，无需再次确认命名与范围。
- 采用 dev 工作流；文档链路与建造链路先独立探索，再记录具体实施分工。
- public/concepts 为文档唯一正文；docs 中旧副本改为入口，旧 HTML 生成链退出。采用 marked 转换，仅允许文档 UI 引入该依赖。
- 保留 ceramic 和原平台内部 ID；显示名统一为暖白岩板、深蓝合金等，不因更名破坏存档。
- 住宅地台全宽 2432 格由 ashlar-B 构成，顶高仍 1.5；不可编辑基础面降至 1。v1 读取仅在内存补地台，保存为 v2 后不重复补回，旧存储不主动改写。
- 方石固定偶数 X 配对合缝，按 128 格分段实例化；实例仍保存每格编号，射线命中返回具体格子。
- 修正架构扫描器把说明字符串中的 self/window 当成全局变量的误报；模板插值与实际全局访问仍接受检查，未改动其他任务的原画资料。
