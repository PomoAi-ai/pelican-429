## Goal

在游戏内提供“角色展示场”开发页面：左侧完整的可搜索多选目录，右侧按所选项目生成多个独立效果预览，支持角色、动作及地上/地下环境的并排对比。每个预览运行固定、紧凑的真实游戏场景，以统一的展示登记方式方便后续新增角色及跟随宠物。

当前授权范围：用户已批准多选对比方案并要求开始开发，执行实现及本地验证。

## Non-goals

- 本任务不制作光灵宠物的模型、跟随 AI 或新动作；保留接入位置。
- 不制作通用关卡编辑器、骨骼编辑器、动画时间轴编辑器、模型导入器。
- 首版不提供任意角度自由旋转、录像导出；同一角色的多个实例并排比较属于首版必需能力。
- 不改写 ECS，不把小鱼强行迁入 Entity，不修改 vendor 模型快照。
- 进入/退出展示场首版通过页面导航；不承诺保存当前游戏瞬时进度。可保留原世界种子及页面参数。

## Acceptance Criteria

1. 游戏设置内可打开“角色展示场”，也可通过 `?mode=showcase` 直接进入；默认游戏入口及 `?level=test` 继续有效，非法模式/角色/动作参数明确报错。
2. 左侧仅展示带真实模型缩略图的角色卡（鹈鹕、训练假人、小鱼），支持搜索、多选和清空；动作只在右侧预览卡内切换。取消勾选移除该角色全部预览。最多 8 张卡，含复制对照，满额禁用新增入口，关闭后恢复。
3. 每张卡片独立切换地上/地下、动作、朝向、播放与速度；支持复制卡片对比同一动作在两种环境下的表现。全局控制可批量应用，区域切换无需整页刷新；保留选择并从动作起点重播，避免跨区域插值与旧状态残留。
4. 动作列表来自各角色显式声明的能力，按钮与真实实现对应；自动准备水池、靶子、弹药、来袭弹等演示条件。
5. 支持播放/暂停、重复演示、重置、0.25/0.5/1 倍速、左右朝向、镜头聚焦/缩放，以及鹈鹕的手动操作。一次性动作重复时先恢复初始条件。
6. 暂停/慢速统一影响模拟、角色程序动画、鱼尾着色器相位、投射物与特效时间；面板保持可操作。
7. 动作切换、角色切换与区域切换均无遗留弹体、伤害、输入锁存、错误相机跟随、累计事件监听；多次切换后 GPU 资源数量不持续增长。
8. 新增展示角色只需新增其展示适配器并在目录登记，面板和展示主循环不增加角色名称分支。新角色自身进入游戏仍需正常实现实体/行为/渲染，不宣称仅靠登记就能生成角色。
9. 所有测试仅在开发机手工执行，不修改 CI。
10. 多张预览的世界、碰撞、弹体、光照、输入与动画缓存互相隔离；支持同时显示多只鹈鹕实例，不共享可变 rig。
11. 默认勾选鹈鹕待机；零选择时右侧显示选择提示，单项时大预览，多项时响应式网格。离屏卡片停止实时推进并显示状态，恢复时不追赶后台时间；同步对比组必须一起暂停/恢复，以共同起点对齐。
12. 多预览共用一个 WebGLRenderer/上下文，逐卡片渲染到独立目标再合成；后期、颜色、深度、裁剪及全局 uniform 不串卡片。可用预览数量以实际性能验证为准，不静默丢弃勾选项。

## Decisions

### 推荐方案：独立展示模式，共用游戏实现

入口分流为正常游戏和角色展示场。展示模式独立装配 UI、相机目标、演示时钟和场景生命周期；共用 Stage、LevelData、SimWorld、实体视图、鱼视图、物理、武器、光照及特效实现。正常游戏入口提取为显式启动函数，避免模块导入即启动。

展示布局以用户最新要求为准：左侧固定宽度目录，右侧完整用于预览网格；动作配置放在对应卡片内。默认选择鹈鹕待机，用户可多选任意已登记项目。每张卡片仅突出一个展示项目，其他角色只在该动作需要时作为靶子、主人或威胁参与。

### 多选目录与对比交互

- 目录按“角色 → 动作分组 → 动作”组织，例如鹈鹕/基础/待机、鹈鹕/基础/走路、小鱼/游动。角色行勾选可选择其全部动作，提供半选状态；搜索只过滤目录显示，不清除已有选择。
- 勾选动作新增对应预览，取消勾选移除该动作的所有预览实例；关闭卡片同步更新目录。一个叶子项有多张卡片时显示实例数量。
- 卡片提供“添加对照”，复制角色、动作、环境和镜头配置并从初始状态创建独立实例。这样可以并排看“鹈鹕走路/地上”和“鹈鹕走路/地下”，也可以看不同角色、不同动作。
- 每卡片显示角色、动作、环境标签，以及播放、暂停、重置、速度、左右朝向、镜头与关闭按钮。卡片修改动作后重新归入对应目录项，避免勾选状态与画面不一致。
- 右侧顶部提供全部播放/暂停、全部重置、统一速度、环境批量应用。独立模式按各自时钟播放；“同步对比”模式从共同起点重播并共用逻辑时间轴，各卡片仍使用各自动作规则。
- 对比相同动作时默认同步尺度、朝向与镜头构图；跨角色可选择统一世界比例或各自适配取景，避免自动缩放掩盖体型差异。
- 单项放大，多项自动排列；多项超出一屏时滚动查看，每张卡片保有最低可读尺寸。首版保证双项/四项对比体验，更多项目保留完整选择并按可见性调度，不承诺无限数量同时满帧。

### 多预览渲染与资源所有权

- 页面拥有唯一 renderer、canvas 与 rAF。每张卡片拥有独立 Scene、camera、模拟世界、rig、光照、动画时钟及后期目标。
- 提取舞台中灯光/相机/环境的共用构造，正常游戏继续沿原单画布方式使用；展示宿主向卡片提供 renderer 与显式尺寸，不允许卡片自行 dispose 共用 renderer 或改整个画布大小。
- 每张卡片先完成自己的模拟、风/降水 uniform 绑定、光照更新及离屏渲染，再合成到右侧对应矩形。清理/恢复 renderer 的 renderTarget、viewport、scissor 和清屏状态。
- 后期需要明确导出最终颜色目标，校验 MSAA/SMAA 缓冲交换和色调映射，合成不能再做一次色调映射；不能假设现有 EffectComposer 会保留外部 scissor。
- 现有 sharedWindUniforms/sharedPrecipUniforms 必须逐卡绑定全部值与纹理，禁止先更新所有世界再统一绘制；暂停的卡片绘制前也恢复自己的快照。全局材质缓存需检查可变 uniform 所有权。
- 首版不共享可变 rig 或已挂接光照的材质对象；只在确认不可变且释放所有权明确时共享资源。卡片内部重置复用自己的 rig，关闭卡片释放其资源。
- 离屏卡片暂停推进和渲染，保留选择与当前状态；同步组任一卡片不可见时整组暂停并提示，回到可见状态后共同恢复，保证时间可比。

### 场地

- 采用固定种子/布局的小型 LevelData，初步尺寸预算为 64×64；这是设计预算，最终根据默认镜头视野、骑车制动距离与飞行净空收敛，不声称已验证最小尺寸。
- 一张小地图内布置地上、地下两个展示区，各有平地、留足净空的空中区域、小水池与演示锚点。
- 地下补齐实体岩层、洞穴掩码及洞壁元数据，使用现有光照图；弱装饰照明下可检验鹈鹕及未来宠物的发光。
- 地上/地下与动作所需的平地/空中/水池是两个维度。例如“地下 + 游泳”自动在地下水池演示。
- 每张卡片切换区域保留选择，停止自己的旧演示、清理旧场景会话，使用同一静态布局建立新的干净运行状态，再聚焦对应区域并重播；其他卡片保持原状态。地图、水、鱼、弹体、事件及动画缓存不能残留。
- 每个卡片持有自己的舞台内容和昂贵的鹈鹕 rig；其场景会话独立拥有视图、光照订阅和模拟数据，先销毁旧视图再在卡片内移交 rig。删除卡片或退出页面时按所有权释放资源。

### 动作范围与驱动

| 角色 | 首版动作/演示 | 驱动方式 |
|---|---|---|
| 鹈鹕 | 待机、走、跑、转向、跳跃/落地、飞行、滑翔、游泳 | 准备地形和出生位置，以 InputFrame 序列驱动 stepSim；循环动作在受控区域运动并在周期边界重置 |
| 鹈鹕 | 啄击、喷水、吐鱼、光球蓄力/发射、吞弹反吐 | 准备武器、资源、目标与来袭弹，通过真实武器逻辑推进，复用事件和嘴囊/弹体效果 |
| 鹈鹕 | 上车、骑行、下车 | 复用 ride 状态机；地下净空充足，动作互斥遵守正式游戏约束 |
| 训练假人 | 站立、受击/击退、射击、倒下后重置、水中漂浮 | 使用实际攻击/射击/物理与生命重置；不虚构走路或骨骼死亡动画 |
| 小鱼 | 游动、受惊逃离、搁浅扑腾、重新入水 | 使用真实鱼群逻辑；明确控制鹈鹕威胁位置和水陆位置，固定 seed 可复现配色 |

不把每种组合都列成独立按钮；例如移动同时射击属于后续组合回归场景。首版覆盖角色已经实现的主要独立能力。UI 可按动作分组显示当前阶段（如“准备来袭弹 → 吞入 → 反吐”），准备期不能伪装成动作无效。

一个动作定义包含：id、名称、所需场地、是否可重复、最大执行 tick、适配器的准备/输入/完成判定。超时或条件缺失明确报错，防止永久等待。初始化专用夹具可设置初始弹药、位置和生命；连续播放由真实系统推进，不每帧硬写表现状态。

### 扩展接口

- `ShowcaseCatalog`：保存角色元信息、适配器和动作声明，校验唯一 id 与完整映射。
- 每种角色的 `ShowcaseActorAdapter`：准备会话、返回相机聚焦点/状态、给出演示输入或场景刺激、判定完成并清理。
- UI 仅接收 `config/showcase.ts` 中可序列化的角色/动作描述和回调；不直接写 world 或引用渲染运行时，也不从 app 层导入类型，以遵守现有 UI 分层规则。
- 通用 runner 只依赖适配器约定；不增加针对 pelican/fish/dummy 的分支。
- 未来光灵可声明悬浮、跟随、加速追赶、发光等能力，通过适配器提供主人及路线夹具。这些是未来能力示例，不视为当前已实现。

### 时间与输入

- 速度档乘在进入固定步长累加器的时间上，保留正式 sim.step。
- 同一演示时间驱动程序动画、鱼尾、水、风、弹体和粒子；暂停冻结场景，UI 使用独立页面时钟。
- hitstop 继续按游戏原有规则冻结相关角色/战斗动画；不把慢速误用为改变每 tick 物理 dt。
- 自动演示和手动输入互斥；手动只开放已支持输入控制的鹈鹕，且只能作用于当前明确激活的卡片。点击另一张卡片、失焦或删除卡片时清空锁存，操作面板不触发角色攻击。
- 重置同时清空输入锁存、stepper 累积、prev/cur、动画/步态缓存和相机过渡。首版不做任意时间倒放或时间轴拖拽。

### Alternatives considered

1. 在 `?level=test` 上继续叠加调试按钮：开发入口最少，但完整 HUD/大地图、玩家相机和暂停规则耦合，新增非玩家角色不便。未采用。
2. 单独做 Three.js 模型查看页：纯模型浏览简单，但无法验证游泳、骑行、吞吐、击退及真实洞穴光照，后续容易出现演示与游戏不一致。未采用。
3. 先重构为通用角色/ECS/场景编辑平台：扩展面广，但远超当前目的，迁移现有鹈鹕和独立鱼群成本高。未采用。
4. 每张卡片直接创建完整 Stage/WebGLRenderer：最容易复用现有代码，但会累计浏览器 WebGL 上下文和重复 GPU 资源，不适合左侧多选持续扩展。未采用。
5. 把所有勾选角色放进同一个模拟世界：可以合照，但攻击、灯光与物理会互相影响，无法独立比较地上/地下和不同动作。未采用。

## Delivery Sequence and Risks

1. 先验证共享 renderer 的双卡片渲染，使用两个独立鹈鹕实例及地上/地下不同光照，确认后期和可变状态隔离。
2. 交付左侧目录多选、右侧响应式网格、添加/删除/复制对照及独立环境设置。
3. 接入三类角色的全部主要动作、单卡与全局控制、同步对比和焦点路由。
4. 完成离屏调度、资源释放、多卡片性能与普通游戏回归，补充新角色接入说明。

技术可行性高；相比单场景方案，复杂度提升到中等偏上，新增的主要工作是多视图后期渲染、可变材质/环境隔离、独立 rig、选择状态一致性和同步时钟。动作夹具与会话重置仍需覆盖吞弹反吐、骑行及独立鱼群系统。

64×64 布局、切换耗时与帧率尚未实测；小地图会减少世界构造规模，但不保证消除鹈鹕 rig 和着色器编译成本。资源复用的所有权需有针对性验证。
