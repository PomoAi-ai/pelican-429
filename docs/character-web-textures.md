# 角色 Web 资源

游戏和展示场默认共用最大512×512的KTX2贴图及18位模型数据压缩版（`textures=ktx2-compact`）。原始GLB、512 WebP和无损模型数据的KTX2版本均保留，可分别用 `textures=original` / `textures=web` / `textures=ktx2` 对比。

## 模型数据同步压缩

256KTX2九份角色共12.408MB，其中贴图仅1.217MB；网格属性7.603MB、索引1.387MB才是主要部分。因此进一步压缩浮点顶点、法线、UV、蒙皮权重、morph和动画输出，使用已安装MeshoptEncoder的18位EXPONENTIAL/SharedComponent过滤，再用现有Meshopt压缩。无收益视图保持原编码。

- `npm run assets:compact` 从既有512/256 KTX2生成独立 `.ktx2-compact.glb` / `.ktx2-256-compact.glb`；重新导出原件时先重建对应KTX2，再运行本脚本。
- 两档每档24张图片逐字节不变；索引、JOINTS、逆绑定矩阵、动画时间也逐字节不变，所有节点/网格/骨骼/挂点/动作/morph名称保留。量化后重算accessor min/max，包括sparse覆盖。
- 最大浮点绝对误差0.0000152588，蒙皮四权重和最大变化0.0000153705，动画四元数最大角度误差0.0009134°。这些为本次资源实测值，不是任意未来模型的统一上限。
- 压缩减少传输/存储体积；面数、绘制调用及解码后的FLOAT32布局不变，未宣称渲染帧率或顶点显存收益。未删除骨骼或抽掉动作。

|---|---:|---:|---:|
| 9角色，512 | 15,014,256 B | 11,910,332 B | 20.67% |
| 9角色，256 | 12,408,408 B | 9,304,216 B | 25.02% |
| Sam怪物，256 | 1,030,384 B | 763,944 B | 25.86% |

对比页新增“同步压缩模型数据（KTX2两栏）”开关，保持同一镜头、观察点、动作和时间；可开关检查同一512/256贴图下的模型数据优化前后。卡片展示完整GLB大小及额外减少比例。角色展示场也可选择“512/256 · 贴图＋模型压缩”。默认游戏用512 compact，256 compact需显式选用。

独立审查使用真实GLTFLoader解析18个compact GLB（Node中仅内存去掉图片引用），动作数、轨道数、时间、时长均一致；检查28处sparse及bounds通过。每份资源的原始SHA、优化前SHA、数据误差和字节数见两份 `ktx2[-256]-compact-models-report.json`。

## KTX2 默认版本

- 颜色：ETC1S q255、sRGB；法线：UASTC quality2、linear，保留XYZ，不使用需要额外着色器重建的RG法线重排。
- 材质数据：UASTC quality2、RDO lambda0.5、linear；UASTC用Zstd18压缩。全部24张贴图512×512，带完整10级mip。
- 文件为独立的 `.ktx2.glb`，使用必需的 `KHR_texture_basisu`。模型几何、索引、morph、骨骼、动画保持无损，与原件逐字节比对。
- 使用Khronos KTX-Software4.4.2的toktx和ktx生成/验证。运行 `npm run assets:ktx2`；若工具不在PATH，设置 `TOKTX=/path/to/toktx`，同目录须有ktx。离线直接读取原始PNG，不从WebP再压缩。
- 浏览器由three自带KTX2Loader检测真实renderer能力，转码器JS/WASM由Vite输出带哈希的本地资源，支持子路径部署；不依赖第三方CDN。设备没有兼容GPU压缩格式时，three可能输出RGBA纹理，内存收益需按实际设备测量。
- 一个页面共用一个转码器，最多2个worker。退出时等待当前下载、初始化和转码结算再释放，避免提前终止worker使加载Promise悬空。

## 展示场对比

独立画质对比页 `?mode=compare` 的入口位于角色展示场“角色场景 / 历史资料”旁。页面并排显示原始、1K WebP、512 WebP、512 KTX2、256 KTX2；共用一个 WebGL renderer、游戏 rig/材质/动画与同步镜头。支持拖动旋转、滚轮拉近、平移、全身/面部/衣服对焦、动作播放/暂停和时间定位。暂停时按需重画，屏外栏目不渲染。

新增两档均直接从原始资源生成，保留既有文件：`npm run assets:web-1k` 生成 `.web-1k.glb`，`npm run assets:ktx2-256` 生成 `.ktx2-256.glb`。256 使用与512相同的 KTX2 编码策略，带完整9级 mip；两档都保留无损 Meshopt 模型数据。对应报告为 `web-1k-models-report.json` 和 `ktx2-256-models-report.json`。

九份模型合计：1K WebP 22,025,384 B，512 KTX2 15,014,256 B，256 KTX2 12,408,408 B；256 比512 KTX2减少17.36%。Sam怪物为2,743,100 / 1,384,636 / 1,030,384 B（依次为1K WebP / 512 KTX2 / 256 KTX2）。256仍包含完整几何、骨骼和动画，因此整份GLB不等于单张贴图体积。

页面每栏列出真实贴图尺寸、GLB文件体积和纹理预算。Sam的256 KTX2按ASTC4×4/BC7含mip约0.25MiB，512约1MiB；此处是理论纹理预算，非完整驱动显存实测，也未测量FPS或冷启动耗时。原件Grassy为1K，其余有图片的角色通常2K，守门人没有图片贴图，按真实报告标注。

角色展示场顶部“贴图对比”可切换KTX2·512、WebP·512、原始高清。切换重载后保留角色列表（含双形态与动作）、朝向、播放/暂停、场景环境、缩放和镜头角度；动画从所选动作起点开始，不保存当前动画秒数。

角色展示场镜头支持滚轮、双指和滑块拉近（0.65–12倍），左键/右键拖动或单指平移；“重置镜头”恢复1倍和默认居中。使用真实相机距离变化，近裁剪面为0.05。切换贴图时保留倍率，平移位置暂不写入网址。

本轮没有做模型减面、顶点量化或动画精简。若后续实施这类有损模型优化，保留原件并继续复用游戏共享加载器进行画面对比。

## 场景背景与加载

首页、主线堡垒、机房预览统一复用4张1536×1024 WebP背景，合计764,582B，原PNG合计7,015,056B，减少6,250,474B（89.1%）。`textures=original`可对照PNG；两者分辨率一致。背景显存并未因WebP文件缩小而减少。

主线直接进入时背景与角色模型并行加载。新故事序章只预取7份GLB字节，建立游戏WebGL上下文后再转码，避免无renderer时错误解码，也避免跨场景重复请求。必要资源全部就绪才建立角色视图；预加载失败、退出和迟到资源各自有释放者。

部署目标是GitHub Pages，仓库没有可控制的HTTP服务配置；未修改CI或生成不能自动生效的预压缩响应文件。

## KTX2 本轮验证

typecheck、npm test、build各执行一次并通过；全量1740/1740用例通过。构建实际输出本地转码器JS/WASM；最大场景JS仍有超过500kB的提示。

浏览器确认展示场三档切换、自由世界、新故事预热到主线、存档直接主线均正常，无控制台warn/error。新故事的7份GLB从预取到进入游戏只请求一次；直接主线的背景请求与模型请求开始时间重叠。

真实GPU上传采集：Sam三张贴图共30级上传，使用sRGB BC7和RGBA ASTC4×4，共1,048,656B，对比RGBA8+mip理论4,194,300B减少约75%。这只是该角色贴图的实际上传数据，不是完整驱动显存读数；没有受控FPS或冷启动耗时对比。

主线模型、4张背景及首次转码器合计13,533,556B；上轮WebP模型+PNG背景为18,697,204B，同口径减少5,163,648B（27.6%），不含其余JS和页面资源。自由世界模型为12,254,576B，KTX2并不减少这一部分下载量。

## 保留的 WebP 版本规格

- 颜色：线性光降采样、WebP Q90；透明度逐像素校验。
- 法线：按数值降采样并重新归一化，随后无损 WebP 编码。
- 金属度/粗糙度：数值降采样、无损 WebP 编码。
- 顶点、索引、稀疏 morph、骨骼和动画：EXT_meshopt_compression 无损编码。使用 INDICES 保留索引顺序；不做减面、量化、重排或动画删帧。
- UINT8 稀疏索引及不足以抵消编码元数据开销的小视图保持原始格式。每个非图片视图解码后逐字节验证，节点/材质等其他字段保持不变。

清单由 src/config/web-models.ts 共享：Grassy 游戏版、Sam/Tibo 两种形态、4种敌人，共9份模型。守门人没有贴图，只压缩模型数据。Grassy 精细版、轻量版及历史模型继续使用原始文件。

## 重新生成

本机需 Node.js 22.18+、ImageMagick（magick）和 libwebp（cwebp）。meshoptimizer@0.22.0 是锁定的开发依赖，仅用于编码；浏览器复用 three@0.180.0 附带的 MeshoptDecoder。

运行 npm run assets:web，从原始源文件直接生成同目录 .web.glb，不从上一轮压缩图片继续降采样。源模型重新导出后必须重新运行。日常 npm run build 使用已生成资源，不在构建时执行压缩。

脚本接受单内嵌 BIN、PNG 贴图的源 GLB；编码结果使用必需的 EXT_texture_webp 和 EXT_meshopt_compression。没有附带原始图片或未压缩几何备份，也不做网络失败后改读原件的静默回退。原件仍独立保留。

工具版本、源文件 SHA-256、每张图片的尺寸/字节量、非图片编码前后字节量均记录在 assets/characters/web-models-report.json。

## 高清入口

- 主线：?mode=story&textures=original

## WebGL 收益边界

单张1K→512的像素数量再减少75%，2K→512减少93.75%。这组角色资源在每个游戏场景的 RGBA8＋完整 mip 链理论预算由上轮约96MiB降至24MiB；全部8组贴图总预算128→32MiB。此值不含场景图片、其他纹理和驱动开销，不是实测显存。

WebP压缩针对传输；解码后仍为普通WebGL纹理，不是KTX2 GPU块压缩。Meshopt也不减少解码后的面数和绘制调用。未测量实际FPS或受控网络加载时间。512在近景下可能降低衣服、毛发等细节，高清原件保留。
